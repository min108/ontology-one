## 接口与安全边界

新增 model.configure（原统一模型配置函数）、backup.export（当前机构延迟二进制下载入口）、backup.restore。下载无新增票据/持久记录，实际下载再次通过权限网关与原归档服务；会话、CSRF、机构绑定与完整响应体期间的请求代次隔离保持。模型配置入口在认证后、JSON 解析前流式限制 16 KiB，保存错误不回显输入；审计只含能力/结果码/计数/耗时。

恢复只允许服务端可信 CapabilityContext.offline 并要求独占维护锁，复用原 validate_archive、validate_snapshot、restore_snapshot；rest/tool/mcp/recipe 均不能恢复。原 CLI 仍直接调用同一 restore_snapshot，仍只允许同机构空工作区、合法归档与维护锁；没有在线恢复路由。系统页只返回版本/实际迁移状态，备份列表只列本部署通过完整结构/文件校验的升级备份，不返回数据库名、路径或其他机构目录。

管理四页保持三旧角色入口。非管理员模型只读、备份只读说明，集成应用仅管理员，源码下载仅总部超管。跨机构维护不能验证模型。模型与运行显示服务配置、运行可用性、版本和安全失败原因，就绪诊断明确仍是 R1 的有限检查。保留所有 demo 功能于原 DemoWorkspace，不改治理权限。

## 自行裁决

- 二进制能力输出安全下载描述符，实际文件生成在再次鉴权的 GET 绑定执行，不把大 ZIP 转为 JSON，不落地下载票据。
- 显式 offline 绑定不复用 recipe，避免把 L3 恢复当成自动配方。
- 运行方式按实际操作系统显示 Windows/服务端，不声称检测到未验证的容器类型。
- 升级列表只显示可完整校验的本部署备份；损坏/缺件备份不宣称可恢复。无完成项时明确“没有可完整校验的备份”。
- 原 registry 五能力测试名称保留；全表等式扩为本支线的显式八项，五个旧读能力仍逐项验证原 read/L0 合约，角色矩阵对全部八项执行。未放宽为子集。
- 离线 URL 只新增 ModelPage.tsx 的模型默认值与 BackupPage.tsx 的点击 href 两个精确源位置；其它位置/主动 fetch 均拒绝。

## 启发式检查

模型页一个主动作“保存统一配置”，连接验证为次动作；地址/模型默认折叠，密钥不持久保存到浏览器。备份页主动作导出，恢复仅说明；错误重试确实重跑操作，字段保留；未配置可返回工作台走人工路径。非管理员可以读取说明，无权限动作禁用且说明管理员职责。所有新表单加入切机构未保存防护。源码出口仅给符合权限者；公网发行链接只在点击时访问。系统无静态“已启用”假状态。新样式全部设计令牌，正文 15px；键盘/1366 布局与最终视觉由浏览器验收记录。
