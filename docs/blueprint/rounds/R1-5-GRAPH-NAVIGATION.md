# R1-5 图谱迟到视口回调修复

实际浏览器中，图谱自动适应画布的动画尚未结束时进入建设工作区，迟到的 `onMoveEnd` 会继续调用旧 `setSearchParams`，将地址从 `/build` 拉回 `/graph?vx=…`。InstanceGraph 的实例视口回调存在相同问题；图谱与实例图之间切换时，旧回调还会污染新视角的查询参数。

GraphWorkbench 与 InstanceGraph 均使用布局效应登记组件存活状态，卸载时立即作废。视口保存首先验证组件仍存活、工作区尚未离开；仅有效页面继续保存既有视口参数。没有延迟导航或等待动画，也没有改动旧 API 请求封装。

新增真实页面组件测试，mock ReactFlow 仅捕获其 `onMoveEnd`，在真实 BrowserRouter 导航完成后主动交付已捕获的迟到回调。两个页面分别覆盖：仍挂载时保存视口、离开至建设页、切换图谱类型、机构切换已进入 leaving 而组件尚未卸载。全部运行于 StrictMode。修复前 6 个故障反例失败、2 个正常保存用例通过；修复后 8 项全部通过。

类型检查、lint、format、legacy 清单检查与 diff 空白检查通过。legacy/api.ts SHA256 保持 `677bd70d30a3fefcec350d2fab76d47e339deccc932266257f02b37790315958`。浏览器故障最终复验由根外壳工作树集成后完成。

## Suspense 保留旧页面的补验

第一次存活状态修复未覆盖 React 路由过渡：目标懒加载尚未完成时，浏览器地址已改变，但 Suspense 仍显示旧画布，布局效应清理尚未执行。根浏览器回归仍复现返回图谱，不能将第一次组件测试通过视为该浏览器问题已解决。

补充回调执行当时的地址所有权检查：浏览器 pathname 必须与该图谱组件的路由 pathname 相同；普通图谱不能写入 `view=instances` 地址，实例图也不能写入已离开实例模式的地址。检测发生在任何 zoom 状态或 URL 写入之前，与卸载标志、工作区 leaving 检查共同生效。

新增两个图谱分别进入建设页、切换另一图谱类型的 4 项反例。目标组件通过未 resolve 的 React.lazy Promise 暂停，真实 BrowserRouter 执行导航；测试确认原画布仍为同一个可见 DOM、没有出现 Suspense fallback，然后交付捕获的旧回调。修复前这 4 项全部失败、原 8 项通过；补充地址检查后共 12 项通过。类型、lint、format、diff 检查通过；旧 API 字节未变。最终浏览器验收仍由根合并后重跑，不以等待动画规避。

## 固定挂载路径的补验

根浏览器在 125% 等效视口下继续发现返航。第二次检查仍以每次渲染读取的 Location 为路径依据：旧路由内容被保留时，Location Context 可以先更新到目的页，使旧组件把目的页路径误认为自己的路径。

两个页面改为用 ref 固定首次挂载路径，后续 Context 更新不得改变该所有权。原有普通图谱/实例模式检查、卸载检查、工作区离开检查继续保留。

新增两个组件反例，保留旧 `/graph` Route match，向保留的页面提供新的 `/build` Location Context；确认同一个画布 DOM 仍可见，再执行该组件新一次渲染提供的回调。修复前两个反例均失败（目标 URL 被添加旧图谱视口参数），原 12 项通过；固定挂载路径后 14 项全过。此反例覆盖了第二次测试遗漏的 Context 先更新，而不仅是使用导航前捕获的回调。类型、lint、format 检查通过；最终真实浏览器结论仍需由根集成复验。
