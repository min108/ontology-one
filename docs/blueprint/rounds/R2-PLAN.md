## 1 目标：汇报时能现场走通的主线

1. **交进来**：在工作台拖入一份制度文档，系统自动发起“整理”，任务托盘显示阶段进度。
2. **看一眼**：整理完成后进入建设方案核对页，条目按把握程度分三档，每条有一句话结论和原文高亮。
3. **点通过**：“采纳并提交审核” → 审核人员在审核中心“通过并发布”。
4. **问一个问题**：在应用助手中就这份制度提问，得到带出处的回答。
5. **出一份报告**：把回答生成 Word 与网页报告并下载，报告中的引用能回到原文。
6. 其余 0.7.0 功能（台账、数据源、经验、技能、权责、图谱、集团成果、集成应用）在新外壳中照常可用，作为“功能完备”的另一半。

- **复用优先**：0.7.0 已有材料上传、阅读分段、AI 候选提炼（`material_extract` 任务）、候选采纳为草稿、要素审核与发布动作、只读应用助手（会话、流式、引用）。本轮在它们之上新建主线界面与必要的新服务，不重写这些能力。

- **不下线旧页面**：本轮新页面与旧页面并存，旧页面入口保留，因此不做附录 A.2 对照。
- **验证按守则**：快速层 CI；完整层最多 2 次；每个新页面一条主路径端到端和 1 张截图。

### S1 建设方案 + 配方 A 主链 + 核对页

- **数据**：`changesets`、`changeset_items`（§5.2 建表语句）与 `recipe_runs`（§5.5.3），机构库迁移 `0002`；字段按蓝图建全，逻辑只实现主路径；状态取附录 C.2。
- **配方 A（基础）**：一个后台任务按顺序执行：上传后的自动分段（复用旧阅读分段，默认方式，无需用户选择）→ 提炼候选（复用 `material_extract` 与其提示词）→ **逐字引文定位**（引文必须逐字出现在原文并生成锚点，定位失败的条目把握程度降为“存疑”，不得凭空生成锚点）→ 写入建设方案条目。阶段文案进任务托盘。无模型时按条款切分兜底并标注识别方式。
- **把握程度**：按 §5.5.5 用确定性规则计算三档；分档线用默认值。
- **核对页** `/build/changesets/:id`：三档分组；每条显示一句话结论、种类、原文高亮；动作：采纳、改一改、不要、全部采纳高把握、采纳并提交审核。采纳即写草稿（复用旧的候选采纳），提交即走旧的提交审核动作。
- **能力**：`changeset.get`、`changeset.decide_items`、`changeset.apply`、`changeset.apply_and_submit`、`recipe.start`、`recipe.status`（附录 D 编号）。
- **测试**：契约与越权测试；一条端到端：上传示例制度 → 生成方案 → 采纳并提交（用 `MockRuntime` 或旧的合成模型服务）。

### S2 审核中心基础版

- `/govern/reviews`：收件箱列出本机构“待审核”的要素（含经 S1 提交的），可按种类筛选；详情显示内容、出处与提交人。
- 动作：通过并发布、退回（填理由）。复用旧的审核动作与职责分离（提交人与最后编辑人不得审核，D4）。
- 测试：职责分离与越权测试；一条端到端。

### S3 从助手回答生成报告

- 入口：0.7.0 应用助手（`/applications`）中一次已完成的回答旁增加“生成报告”。可以通过新页面调用旧会话接口实现，也可以在旧页面最小改动加按钮；选更省的一种。
- 规格：§7.2 的最小子集——标题、正文段落、表格、引用；数值必须来自回答中的工具结果或引用（§7.3 数值核验，不通过即阻断并提示）。
- 渲染：Word（`python-docx`，公文版式的基本样式：标题、正文、表格、页码）与自包含网页（文本节点写入、内容安全策略、无外链）。
- 保存为成果（`artifacts` 表或先存为受控文件并登记），可下载、可再次生成。
- 测试：渲染器单元测试（含注入样例：标题和单元格里的脚本与公式不被执行）；一条端到端。

### S4 演示环境与演练脚本

- 一条命令启动并装载演示资料：`docker compose` 起服务 → 管理员登录 → “管理 › 演示资料”加载 0.7.0 演示包（内含模拟核对说明、合同与付款台账、示例问题与核对基准）。
