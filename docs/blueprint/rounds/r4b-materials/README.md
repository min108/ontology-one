# R4-B 验收用检索用例

规划方 2026-11-19 准备。检索的验收不用为检索专门造的数据，而用主线真实产生的内容：先按 R4-A.1 的做法把 `../r4a1-materials/regulation-plain.txt` 交进来、核对、提交、由另一人审核发布，再按下表检索。期望结果按**原文片段**描述，不依赖模型给条目起的名字。不得为了命中而改写制度原文、给条目补关键词或调整期望。

| # | 身份 | 输入 | 期望 |
|---|---|---|---|
| S1 | 建设人员 | `10个工作日` | 前 5 条里有一条已发布规则，它的出处引文含“验收通过后10个工作日内提出付款申请” |
| S2 | 建设人员 | `预付款比例` | 前 5 条里有出处引文含“预付款比例不得超过合同总金额的30%”的规则 |
| S3 | 建设人员 | 任一已发布规则名称里连续的 4 个字 | 该规则排第一 |
| S4 | 建设人员 | 该规则的完整编号 | 该规则排第一 |
| S5 | 建设人员 | 先给一条已发布内容登记别名“质量保证金”并重新发布，再输入 `质量保证金` | 命中这条内容；输入它的正式名称同样命中 |
| S6 | 建设人员 | `一次性告知经办部门补正` | 既命中引用这句话的规则，也命中制度原文的对应片段；同一份材料最多出现两段 |
| S7 | 建设人员；只能看已发布内容的身份 | 一条未发布草稿名称里的 4 个字 | 建设人员看得到并标明“草稿”；只能看已发布内容的身份看不到 |
| S8 | 建设人员 | `区块链结算` | 明确提示没有找到足够依据，不拿不相关的内容凑数 |
| S9 | 建设人员 | `款`（1 个字） | 不报错；按名称开头匹配给出结果或提示再多输入几个字 |
| S10 | 另一家机构的建设人员 | `10个工作日` | 看不到本机构的任何内容 |
| S11 | 建设人员 | 旧搜索入口（旧页面的搜索框、`/api/search`、`/api/entities?q=`）输入 `预付款比例` | 与新检索的结果一致（同一批内容、同样的先后） |
| S12 | 管理员 | 清空索引后运行重建任务，再重复 S1–S6 | 结果与重建前一致 |

性能只测一次并如实报告（R4-PLAN D8）：一家机构 1 万条内容时，S1 这类查询连续 200 次的 95 分位耗时。这 1 万条可以用合成内容，但要在报告里写明构成。
