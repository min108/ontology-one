# R2 十分钟演练（1.1.0）

准备 Docker Compose；首次构建需能下载锁定镜像与依赖；企业代理环境可通过 `SSL_CERT_FILE` 注入构建证书，并只读挂载给运行容器，保持 TLS 校验。运行目录为仓库根目录。演示项目 `ontology-r2-demo` 使用独立卷，不复用原部署的数据。

```bash
# 在当前终端输入真实模型密钥；输入不回显，不写入文件或命令历史。
read -rsp 'DeepSeek API key: ' DEEPSEEK_API_KEY; export DEEPSEEK_API_KEY; echo
python3 scripts/start_r2_demo.py
```

脚本询问演示账号密码，一条命令完成 Compose 启动、迁移、三个演示身份初始化和原0.7.0演示资料装载。数据库凭据仅存于本机 `work/r2-demo/database.env`，不要删除它后复用原卷。模型密钥只来自进程环境。后续重启仍先在终端设置密钥，再执行同一命令。

打开 `http://localhost:8765`；账号 `demo.admin`、`demo.builder`、`demo.reviewer` 使用刚输入的演示密码。首次登录管理员，在“管理 › 模型与运行”核对模型并点“测试连接”；本轮环境配置模式不在网页输入或保存密钥。到“管理 › 演示资料”可查看已装载的模拟核对说明、合同/付款台账、示例问题与核对基准，必要时可点“加载演示资料”。

## 五步演练

1. **交进来（约2分钟）**：以 `demo.builder` 登录工作台。把下方两条合成制度另存为 UTF-8 文本，文件名为 `【演示】付款核对制度.txt`；把文件拖入工作台或顶栏，零必填对话框点“开始整理”（也可从建设 › 制度整理选择文件）。任务托盘显示分段、提炼、定位原文、生成方案；页面完成后点“核对建设方案”。
2. **看一眼（约2分钟）**：查看高把握、需核对、存疑三组；点“查看原文”确认逐字高亮。采纳付款申请时限条目，或用“改一改”调整；也可全部采纳高把握。没有模型时会明确显示本地规则识别，归入存疑，不能作为真实模型效果展示。
3. **点通过（约2分钟）**：点“采纳并提交审核”。另一个浏览器会话以 `demo.reviewer` 登录，治理 › 审核中心，选中条目，核对正文、出处和提交人，再点“通过并发布”。提交人及最后编辑人不能自己审核，管理员也不能绕过。
4. **问一个问题（约2分钟）**：回到建设人员的“应用 › 应用助手”，展开参考范围，关闭自动选用，选中刚发布的制度。问：“请阅读所选制度，说明付款前要核对什么，以及验收通过后的付款申请时限。用一段说明和一个两列表格回答，保留准确数字并注明原文依据。”预期回答包含原文支持的30日期限，参考来源链接可打开要素。
5. **出一份报告（约2分钟）**：已完成回答旁点“生成报告”；报告默认本人私有。查看依据清单并打开原文，下载 Word 与自包含网页。Word 具有标题、正文、表格、页码；网页可离线查看正文及引用原文。再次生成产生新版本，报告列表可重新打开下载。若数字没有对应到引用，会阻断并列出数字与段落；回到助手要求核对这些数字及原文后重新生成。

合成制度（不代表实际业务规则；与演示台账“累计付款不超过合同金额”的核对口径一致）：

```text
第一条 办理付款前应核对合同约定与验收资料；验收通过后30日内完成付款申请。
第二条 累计付款不得超过合同金额；有异议的款项应记录原因并暂停支付。
```

在“本体 › 本体目录”搜索刚发布的条目，可查看业务语言卡及结构化信息、关系、版本、动态；编辑仍回原页面。

## 自动复现与收尾

开发环境已经安装锁定依赖、MySQL及Chromium时，可运行 `.venv/bin/python e2e/run_r2.py --output work/evidence/r2/mock`；真实模型在环境中配置后加 `--live`。仅使用临时数据库，退出自动删除；真实模型演练记录各步骤耗时、成败及必要的数字错误码；数字门拒绝时按第5步要求模型修订一次，仍须通过相同校验。不保存回答原文、截图或密钥。Linux运行需可写的真实tmpfs，见 `R1-PREFLIGHT.md`。

停止演示：`docker compose --project-name ontology-r2-demo --env-file work/r2-demo/database.env down`，保留卷以便下次继续。演练结果与尚需负责人验证的项目见唯一轮末报告 `R2-REPORT.md`。
