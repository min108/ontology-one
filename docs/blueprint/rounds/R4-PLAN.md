## 0 为什么分两段

蓝图 R2 是一整轮的内核工作（十个工作包，后端测试增量不少于 190 个）。一次交付验收面太大，问题会叠在一起。本轮分 **A、B 两段**，每段独立交付、独立验收，A 段通过后再启动 B 段；版本号在 A 段升为 1.3.0，B 段沿用。

| 段 | 工作包 | 一句话 |
|---|---|---|
| **A 内核与门禁** | R2-1 种类注册表与侧表、R2-2 要素服务、R2-3 关系扩展、R2-4 业务语言卡、R2-6 表达式与规则口径、R2-7 五项门禁；R3 遗留 | 内核立起来，门禁在主线里真正生效 |
| **B 组织、检索与目录** | R2-5 机构本体与发布版本、R2-8 检索与语义服务、R2-9 目录与要素页补齐（含可见范围与敏感级别、`analyst`/`viewer`）、R2-10 迁移验证与旧页下线 | 内容能组织、能找到、能按权限看到，旧页退场 |

## 1 本轮结束时负责人能看到的

1. 任一存量要素打开都是业务语言卡首屏，出处可在依据抽屉高亮原文。
2. 能建出“业务对象—对象关系—数据项—指标口径—术语—规则（含判定式）—业务流程”一组内容，派生关系自动出现；规则的判定式有一句对应的中文，测试用例能运行。
3. 五项门禁在提交审核、审核、发布三处生效，不通过时用业务语言写明“还差什么”；审核人员可对出处、条件两项写理由豁免并留痕。R3 中审核中心与要素页里固定显示“待审核确认”的检查项，换成真实门禁结果。
4. （B 段）机构公共部分与发布版本可用；检索能按别名、编号、正文片段命中；本体目录与要素页补齐；受限内容按可见范围隐藏；`analyst`、`viewer` 账户可用；旧的业务资产、资产详情、知识专栏三页按对照清单退场。
5. 汇报主线照常走通：门禁接入后，交进来 → 看一眼 → 点通过 → 问一个问题 → 出一份报告仍能用真实模型经界面连续 3 次完成。
