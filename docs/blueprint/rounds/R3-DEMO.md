# R3 十分钟主线演练（1.2.0）

## 准备演示环境

在仓库根目录操作，准备 Docker Compose；首次构建需要下载锁定镜像与依赖。企业代理可通过 `SSL_CERT_FILE` 注入构建证书并只读挂载给运行容器，保持 TLS 校验。

```bash
# 密钥只输入到当前进程环境；输入不回显，不写入文件或命令历史。
read -rsp 'DeepSeek API key: ' DEEPSEEK_API_KEY; export DEEPSEEK_API_KEY; echo
export ONTOLOGY_MODEL_FROM_ENV=1
python3 scripts/start_r2_demo.py
```

R3 **沿用 `start_r2_demo.py` 名称以兼容已有演示环境**，本轮未新增同名 R3 启动脚本。Compose 项目仍为 `ontology-r2-demo`，使用独立卷，不复用原部署数据。脚本询问演示账号密码，完成启动、迁移、三个身份初始化和演示资料装载。数据库凭据保存在本机 `work/r2-demo/database.env`，保留该文件与原卷的对应关系；后续重启仍先在终端设置模型密钥，再执行同一命令。环境模型覆盖仅适用于演示或单机构部署，默认关闭，迁移服务不接收模型密钥。

打开 `http://localhost:8765`。`demo.admin`、`demo.builder`、`demo.reviewer` 使用刚输入的演示密码。管理员先在“管理 › 模型与运行”点“测试连接”，确认模型可用；环境配置模式不在网页输入或保存密钥。“管理 › 演示资料”可查看模拟核对说明、合同与付款台账；需要时按页面状态加载或恢复。

新账号默认**简洁视图**。旧账号若已保存专业偏好，会保持原选择；演示开始前从账号菜单切回简洁。机构、身份与范围收在顶栏机构选择器，二级入口在左侧工作区内展开；标题与正文共用左边线，页面主要动作在标题右侧。日期按北京时间显示。模拟资料和模拟模型会明确标注，不能当成真实模型效果展示。

## 五步主线

1. **交进来**：`demo.builder` 登录工作台，将下方制度保存为 UTF-8 文件 `【演示】付款核对制度.txt`，拖入工作台或顶栏，在无需填写的对话框点“开始整理”。也可从“建设 › 制度整理”选择文件。观察任务托盘的分段、提炼、原文定位与方案生成阶段；完成后，标题区结论应说明整理条数，点“核对建设方案”。

2. **看一眼，处理全部条目**：先选一条，点“查看原文”；原文在当前页抽屉内逐字高亮。关闭抽屉后，应仍选中同一条，列表位置不变。用“改一改”调整一条表述并保存，再重新查看确认保存结果；不要改动原文支持的30日期限。可“全部采纳高把握”，其余需逐条采纳、改后采纳或“不要”，直到没有未处理条目。采纳与保存不额外弹提交确认；“查看草稿”应进入新要素页并显示草稿状态。没有模型时出现的“本地规则识别”条目须人工核对，不能作为真实智能整理结果展示。

3. **点通过**：未处理完之前，“采纳并提交审核”不可用，旁边说明还有几条；至少采纳一条且全部处理后才可提交。点击后出现一次二级确认对话框（L2），核对将提交的内容、检查结果和影响，再确认。预期主按钮变为“已提交审核”，下一步提示等待其他审核人员。另一个独立浏览器会话由另一位使用人以 `demo.reviewer` 登录“治理 › 审核中心”，逐条核对正文、出处、适用条件与提交人，点“通过并发布”并确认，结果应为已发布。提交人及最后编辑人不能审核自己的内容，管理员也不能绕过。

4. **问一个问题**：在刚发布的要素页点“就此提问”，直接进入应用助手：参考范围已展开，自动选用已关闭，且只选中当前要素，无需再手动寻找或勾选。核对名称后即可输入问题；如需调整范围，仍可取消勾选或重新选择。提问：“请阅读所选制度，说明付款前要核对什么，以及验收通过后的付款申请时限。用一段说明和一个两列表格回答，保留准确数字并注明原文依据。”回答完成后，检查30日期限与引用是否相符；引用应能打开对应要素。已有内容、演示台账和本次上传的制度须按名称区分，避免选错范围。

5. **出一份报告，重开与下载**：已完成回答旁点“生成报告”。首次若因数字或引用核验被拦，系统自动带上核对问题修订回答，并自动重新生成**一次**，无需再点 R2.1 的手动修订入口。成功后报告显示“已按核对结果修订 1 次”，展开“查看修订前后”可对照两版回答；未发生修订时不显示该标记。若修订后仍不通过，页面保留具体问题，由使用人在助手中核对后继续提问，不自动循环、不绕过核验；修订请求失败时可按提示“重试修订”。

   报告默认本人私有。在报告页点引用上标，确认抽屉中的依据、原文与引用一致；展开“报告正文”检查段落和表格。下载 Word 和自包含网页，分别打开确认标题、表格、30日期限与原文引用，网页离线仍可阅读。展开“报告版本”，点“再次生成”，确认版本递增且旧版本仍可下载。最后“返回报告列表”，按标题重新打开同一报告，再下载一次；不能只在首次生成后的页面验证下载。

合成制度仅用于演示，不代表实际业务规则：

```text
第一条 办理付款前应核对合同约定与验收资料；验收通过后30日内完成付款申请。
第二条 累计付款不得超过合同金额；有异议的款项应记录原因并暂停支付。
```

## 补充走查

- **退回再提交**：审核人员另选一项，填明退回理由并确认。确认建设人员可看到已退回状态和理由；补充后重新提交，应再次出现在审核中心，再由另一人审核。
- **简洁与专业**：在“本体 › 本体目录”搜索并打开刚发布要素。默认展示业务内容，条件、关系、版本和动态用折叠行；从账号菜单切专业，查看增加的结构化信息、检查与技术详情，刷新后偏好应保留。切回简洁，内部编号与原始数据不应显示。
- **账号、审计与机构**：管理员在“账号与权限”编辑一名演示账号，从该行“更多”重置密码或停用，核对实际结果；不要停用当前演示所需身份。审计按操作人、机构、操作类型和北京时间日期筛选，表格只显示时间、谁、做了什么、结果；专业视图中点记录、展开技术详情。顶栏切换机构或范围后核对可见内容与只读提示，未保存编辑应先确认；左侧展开各工作区，旧入口应仍可使用。

## 自动复现与结果记录

开发环境已安装锁定依赖、MySQL 和 Chromium 时，从仓库根目录执行。每次 `--output` 使用尚不存在的 `work/` 子目录：

```bash
# 合成模型经真实浏览器与 SDK 的功能演练
.venv/bin/python e2e/run_r3.py --output work/r3-demo/mock

# 中途先跑一次真实模型界面主线，尽早发现不匹配
.venv/bin/python e2e/run_r3.py --live --repetitions 1 --output work/r3-demo/live-early

# 收尾真实模型经界面连续三次；密钥仍只从进程环境读取
.venv/bin/python e2e/run_r3.py --live --repetitions 3 --output work/r3-demo/live-final
```

脚本使用一次性测试数据库并负责清理；Linux 运行需要可写的真实 tmpfs，环境前提见 `R1-PREFLIGHT.md`。记录每次主线成败、首次报告是否被拦、是否触发自动修订、下载与版本结果；验收结论写明界面/接口/单元渠道、真实/模拟模型、本地/CI 环境及提交号。脚本存在或示例命令可执行不代表本轮已经验证，实际结论以 `R3-REPORT.md` 为准。

停止演示并保留卷供下次继续：

```bash
docker compose --project-name ontology-r2-demo --env-file work/r2-demo/database.env down
```
