# R4 A 内核与五项检查演练（1.3.0）

沿用 [R3 演练](R3-DEMO.md) 的隔离 Compose 环境、三个身份、五步操作及报告下载检查。启动脚本仍为 `scripts/start_r2_demo.py`，保留原项目名和卷；密钥只从进程环境读取，不写入网页或文件。本轮真实模型验收配置为 `deepseek-flash`、`https://api.deepseek.com/anthropic`，管理员先测试连接。

## 合成制度

保存为 UTF-8 文本后，由建设人员拖入工作台。它仅用于演练，不代表实际业务制度。

```text
第一条 办理付款前应核对合同约定与验收资料；验收通过后30日内完成付款申请。
第二条 累计付款不得超过合同金额；有异议的款项应记录原因并暂停支付。
第三条 经办人员应保存验收记录，审核人员复核付款依据。
第四条 适用范围：本机构合同付款；适用条件：验收完成；例外：存在争议时暂停付款；生效日期：2026-01-01。金额单位：元；验收记录与付款依据的单位：份；金额与资料的记录粒度：每份合同。
```

## 核对与修复

1. 整理完成打开核对页，逐项展开“五项检查”，查看实际来源、定义、条件、关系、版本结果。制度出处应能打开原文并逐字高亮。
2. 另用删去第四条的文本演练缺项：按钮应不可提交，旁边写明原因。在“改一改”依据真实资料补齐范围、条件、例外、生效日期；原文没有的不能让系统代填事实。
3. 核对分类：本例的规范义务属于规则；模型若误提为技能，依据实际引文在“改一改”改为规则，先保存查看新的适用建议，再点“采纳”。检查默认提出的“适用于〈本机构〉”，或原文指明的已有对象，随采纳确认关系。数据项缺单位或粒度时，依据第四条补齐：金额为“元”，资料为“份”，粒度为“每份合同”；保存后确认预检变化，不能给可执行技能虚构测试或依赖证明。
4. 在要素专业视图编辑规则判定式及两个测试用例，保存后重新运行；指标用例单独保存于“测试用例”，不能塞进公式对象。应显示实际结果，全部通过才满足条件检查。“不符”须同时显示人工核实声明。
5. 采纳并提交后由另一人审核。退回理由应在建设人员页面可见，补充后重提。若另一编辑已改正文，旧页面必须提示版本冲突；刷新查看当前内容并明确保存后才能提交。
6. 历史待审缺出处或条件时，独立审核人员填写理由可豁免 QG1/QG3；确认要素动态留痕、折叠区外有“出处已豁免/条件已豁免”。硬约束出处豁免另显示“该内容的依据仅为访谈、底稿或他人陈述”。QG2/QG4/QG5 不能豁免。历史已发布内容读取仍保持已发布。
7. 按 R3 五步继续“就此提问 → 生成报告 → Word/离线网页 → 再次生成 → 重开下载”。核对有依据的 30 日期限；报告自动修订最多一次，修订结果不可再次修订。

## 自动复现

锁定依赖、Node 22、MySQL 8.4、Chromium 与可写 tmpfs 准备方式见 AGENTS。使用有建库权限的一次性测试实例，每次输出目录必须是新的。

```bash
# 合成模型，包含原 R3 动作及 AA1–AA9；不是实际模型效果
.venv/bin/python e2e/run_r4.py --output work/r4-demo/actions

# 中途真实模型主线一次
.venv/bin/python e2e/run_r4.py --live --repetitions 1 --output work/r4-demo/live-early

# 最终代码连续三次，遇到失败立即停止，不能挑选三次成功拼接
.venv/bin/python e2e/run_r4.py --live --repetitions 3 --output work/r4-demo/live-final
```

回执记录提交、模型、接口地址、每步用时、首次数字拦截、自动修订、逐项门禁及豁免情况、服务和数据库清理。任何清理失败都会使结果失败。AA2 的 200 条包含按旧结构扩充的合成记录，原始夹具只有 26 条，来源在回执中单列。实际验收结论见 [R4-REPORT](R4-REPORT.md)。
