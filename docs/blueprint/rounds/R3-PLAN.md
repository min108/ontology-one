## 0 为什么这一轮先做界面基础

Fable 的独立审视结论是“规范到位、骨架可用、成品感不足”，散乱主要来自：没有统一页面骨架（1920 宽下标题落在 4 个横向位置）、新旧两套视觉语言同屏、外壳横条堆叠（1366×768 下第一行数据从 652px 才开始）、内容没有编辑（说明句、零值、JSON、32 位编号外露）、强调层级太平。它特别指出：**“等主体功能做完再整体打磨”只对表面样式成立，对版面规则和外壳结构不成立——每多建一页，就多一份返工。** 后续九轮还要新建几十个页面，所以页面骨架、外壳、字号阶梯、按钮层级、旧页过渡办法必须现在定下并落地。

本轮同时完成：默认简洁视图、报告数字核验的体验改进、R2 验收遗留的缺陷修复，使汇报主线在新外壳下更稳、更好看。

## 1 本轮结束时负责人能看到的

1. **全站一个页面骨架**：所有新页面标题与正文落在同一条左边线；内容区之上只有顶栏和标题区两条；1366×768 下列表页首屏能看到数据。
2. **主线五步在新页面里顺畅走完**：每页一句结论、唯一主按钮、底部“下一步”条把五步串起来；“查看原文”“查看草稿”不再跳进旧页面。
3. **所有人默认简洁视图**，专业视图有实质差异（编号、技术详情、结构化信息、校验明细等），偏好保存在服务端。
4. **旧页面套上过渡补丁**，与新页面在字体、强调色、圆角、标题、最小字号、左边线上对齐，不再“点一下换一种风格”。
5. **报告首次生成被数字核验拦下时，自动按核对结果修订一次**，用户不用自己点；仍不通过时如实列出问题。
6. R2 验收遗留的缺陷修复（第 3 节 U8）。
