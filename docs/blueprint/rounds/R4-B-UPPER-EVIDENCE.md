## A.2 业务行为变化

1. 自上次发布以来的编辑人和提交人都需由其他审核人员办理，改种类、重新修订、导入和经验修订延续同一段记录。
2. 建包技能、权责、专项及历史条目的新写入口执行原工作面守卫，给出实际可办理的入口。
3. 逐项撤回已通过检查的申请并留痕。无关编辑保留尚缺的申请与原申请人，自己的编辑仍需独立复核，旧批准不可沿用。
4. 存在歧义的日期留空并显示候选原句，选句与手输分别保留操作人、值和依据。
5. 核对页和审核中心分清四种来源；建议主体及系统推断的条件、例外和日期如实显示。
6. 批量确认按条件和例外分别显式勾选，每项直接展示原句；审阅期间引文或版本变化须重选。
7. 逐段显示未形成候选的原文，保留为待核对条目；重试对同一坏候选去重。
8. 已采纳草稿的放弃需要确认，旧版本请求被拦，归档后关闭无效编辑动作。
9. 核对页显示具体缺项及禁止豁免的原因，无可提交项时说明下一步；“去补齐”滚动并聚焦缺口。
10. 审核中心默认展开待办的发布事实；修改判定式时同步生成当前中文句。
11. 升级前已审核的条目可经原入口发布，旧异常判定式的修订、归档、退回保留原件。
12. Excel 导入按现有单位、粒度和实际原始表行生成可审核的草稿及首版快照；省略的计量列保留已有值。

## B1 动作、反例和恢复

BA1–BA6 的版本、角色和恢复验证走真实 MySQL、HTTP 会话及后台执行器，均不调用模型。用于 BA5 的历史场景记录仅在动作开始前准备，其成员来自正常上传、采纳和独立发布。提升、差异计算、引用登记以及草稿复查均经业务入口执行。 [机构升级用例](../../../tests/migrations/test_r4b1.py) · [HTTP 动作](../../../tests/r4b/test_release_actions.py) · [后台与并发动作](../../../tests/r4b/release_worker_actions.py)

| 动作 | 实测结果与可检出的错误 |
|---|---|
| BA1 升级、开通、恢复 | 在原版 0.7 的三个库中逐行校验实体、关系、版本、活动。部门样本计数为 24、10、25、48。完整开通 51 家机构，48 家原先尚未开通，每家有且仅有一个按目录命名的公共部分，迁移重跑新增 0 项。改成固定名称、让 v7 接受 v8、允许覆盖已改动的公共部分，三项变异均被检出。 |
| BA2 首版与独立发布 | 创建人和提交人均不能自审，另一审核人发布后查组成、落库条目和 SHA-256。两路请求同时生成同一草稿，只落一行；送审后新增发布要素，旧申请被拒，未产生冻结条目。调换哈希中元素编号的排序会失败。 |
| BA3 语义版本 | 说明文字、增加资产、归档分别建议修订、次、主版本。另查业务对象属性及标识、规则判定式与指标公式、关系与绑定。下调和占用版本号被拒。把纯说明变化算成次版本能检出。 |
| BA4 冻结与撤回 | 已发布条目不能修改。撤回最新版本后读回原快照并检查当前指针，撤回处理并发时仍保留正确指向。删除回退逻辑会失败。 |
| BA5 场景资产提升 | 从既有场景提升后，业务编号、内容、要素版本与出处相同。旧快照仍为成员；新草稿中该要素转为四字段引用，建议次版本。删除原场景引用留存后，用例会读到主版本删除。真实已确认关系产生依赖；补登后原草稿再次读取即反映已登记。 |
| BA6 角色和只读 | 六种真实登录身份对六个写能力逐项核对。管理员、持有实际归属的建模师、同机构其他建模师及审核人员各有准许和拒绝实例。只读与他机构访问另查。去掉负责人的授权，矩阵会失败；把后台批准与会话解绑，会错误发布已退出审核人的任务。 |

0.7 的便携备份导入了 175 行、4 份原件。24 个原实体编号全保留，22 行逐行哈希相同。原有技能恢复规则会将一份技能送回重新审核并增加一条版本，机构目录根节点恢复时重新生成时间。原 10 条关系、25 条版本和 48 条活动逐行一致。整套部署备份恢复则逐表逐行一致，完成后实启原版 `1359118`。另将两项实际发布的资产、一个场景引用和一个真实依赖通过完整和便携两种路径恢复，在两种情况下，2 条归属记录、1 条依赖、1 个发布版本、11 个冻结项的摘要和经授权读取的版本详情均与备份前相同。

B1 的既有断言调整包括租户迁移级别从 4 变为 5、离线库存同时检查原侧表和四张新增表、三处能力精确清单从 41 项变为 47 项。旧 v1 函数的历史哈希继续保存，B1 单列 `_create_entity`、`_confirm_relation` 两个新哈希，覆盖已确认跨场景关系的依赖登记。账号管理仍只提供原三种角色的分配选项。预置的应用人员和查阅者能登录，管理员改其显示名保留原角色。

| BA6 的 B2 能力 | 以六种已登录身份逐个调用五个读能力，同时核对查阅者看不到的草稿、另一机构资产与只读工作区。把查阅者的已发布检索也拒绝，原应返回 200 的用例得到 403。 |
| BA7（S1–S6） | 浏览器按办理时限、预付比例、四字名称、完整编号、别名与正式名检索。S1、S2 的规则排名第一。补正语句同时命中规则和原文，点开分别到达要素与高亮的原段。较宽的“付款”在原文中能匹配 11 段，同一材料仅返回 2 段。 |
| BA8（S7–S10） | 拥有草稿权限者看到草稿标识，查阅者搜不到同一草稿。他机构的建设人员搜不到当前机构的规则或片段。无依据和单字查询分别给出提示或前缀结果。原 B1 界面的真实截图能命中一条草稿，却缺少状态，S7 断言确实失败。 |
| BA9（S11） | 顶部、维护页、两个 v1 接口及既有会话工具按各自原有筛选范围逐条核对顺序和原字段。向旧搜索注入倒序后，S1–S10 已通过，S11 检出差异。外部 MCP 用真实注册应用再查公开元数据、仅在载荷中出现的词、未发布标题及其他机构标题。 |
| BA10（S12） | 清除派生索引后确认原查询没有结果，由机构管理员启动持久后台任务，完成后七个输入（含 S5 的两个名称）的文档编号与顺序逐项一致。令执行器只完成任务而不写文档，S12 能检出。改名、归档、放弃后立即重查；索引写失败时业务回滚。 |
| BA11 | 真实登录 HTTP 验证按名称、别名、编号解析；以业务读法展开至两跳；按不可变原文、版本及建设路径追溯；计算直接、间接影响及场景依赖。真实数源查询的回执绑定执行者、映射及当前授权。收回与重新授权都重新读取，私有报告、异机构及不可见来源受过滤。截去第二跳、篡改来源版本或漏算间接使用方时，三条断言分别失败。 |

### B1 与 B2 的写入口

A.1/A.2 的 34 个入口沿用上表的六道既有守卫。B1 的六个新能力、一个改道的机构管理入口，加上 B2 的索引重建 REST，合计 **42 个在线业务入口**。另列两个持久任务与离线恢复，它们在第二次执行、恢复或权限变化时仍须核对权限。搜索索引的同事务维护附着在原写入口上。 [机构写入矩阵](../../../tests/r4b/test_release_actions.py) · [工作进程](../../../tests/r4b/release_worker_actions.py) · [索引同步与重建](../../../tests/r4b/test_search_index.py)

| 新增或改道入口 | 适用守卫与被拦用例 |
|---|---|
| `module.save`、`module.move_elements`（2） | 检查机构、只读、实际负责人、唯一归属及实际引用。普通建模师、传入的假负责人和外机构编号被拒；提升保留原内容和既有审核次序。 |
| `release.create_draft`、`release.submit`（2） | 当前机构、管理权限及已锁定的草稿状态。只读和非负责建模师被拒，草稿修改后旧版本号与内容摘要失效。 |
| `release.publish`、`release.withdraw`（2） | 检查审核权限、版本和当前机构。创建人、提交人均不能批准；无审核权限者不能撤回。快照保留要素自己的发布门禁及既有专项记录。 |
| `org.manage`（1） | 机构目录管理员改名时在目标机构同步公共部分和可检索名称。无目录管理权、只读或事务中断时不能留下部分改名。 |
| `POST /api/v2/system/search-index:rebuild`（1） | 复核机构管理员及可写会话。建模师和他机构请求被拒；任务编号只对相应机构可见。 |
| `release_snapshot`、`index_rebuild`（后台 2） | 复核实际申请人、当前会话、机构、持久申请和租约。退出后重新批准才可冻结。越机构或租约失效不能覆盖索引。 |
| 迁移、完整及便携恢复（离线） | 维护锁、目标机构或备份归属、可信恢复版本和原生索引定义逐项验证。单独移除标题或正文的 ngram 解析器时，真实全文查询的中间词失去命中，备份器拒绝当前损坏的表。 |

### B1 与 B2 的业务行为变化

接续 A.2 的 12 条，新增 10 条，合计 **22 条**。

13. 升级和开通机构时建立按机构目录命名的公共部分，机构改名同步到公共部分。
14. 建模师须有真实负责关系才能调整归属；场景提升保留原编号、内容、版本、出处和原场景引用。
15. 发布草稿列出成员、已确认关系、绑定、依赖、门禁和语义版本建议，旧库首版列出存量门禁缺口。
16. 提交后其他审核人员冻结同一个内容版本，内容变化、审核人退出或审批过期时需重新办理。
17. 撤回保留历史快照，当前版本指针落回上一有效发布。
18. 顶部搜索显示状态、业务摘要与命中词，能直达要素或对应原文。无依据时提示，单字按名称前缀处理。
19. 旧搜索与新搜索共用排序；外部应用、跨机构只读和查阅角色按各自权限过滤候选及来源。
20. 保存、归档、放弃和重新确认分段同步更新索引。管理员可用后台任务重建；恢复后从业务数据重建。
21. 建设人员可按名称、别名与编号解析，按业务读法展开关系，查看引用原文、发布版本及修改影响。
22. 管理员可查看已有应用人员或查阅者并改显示名，保存原角色。既有账号创建流程继续使用原三种可分配角色。
