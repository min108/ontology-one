# ADR-0002 渐进迁移与旧页面隔离

状态：已采纳（设计约定，实现进度见 R1-PLAN）　日期：2026-11-16　相关轮次：R1

## 背景

0.7.0 的安全底座与业务功能必须持续可用；新接口、新迁移框架和新外壳须逐步接替，不能一次搬动全部业务模块。

## 备选方案与取舍

全量重写会同时改变权限、存储和界面，难以独立归因；直接覆盖旧样式会污染旧页面；每次启动升级和备份会破坏 Windows 启动时限。因此采用逐域替换、样式隔离和显式迁移入口。

## 决定

1. 新能力进入新包；v1 保留原行为。main.py 的内联路由原样搬到 api/v1/core.py，保留旧名称转发，单独核验 AST 和路由集合。
2. 旧前端整体进入 legacy，选择器在构建时限定到 .legacy-root；门户弹窗使用同样的隔离容器。新旧类型检查分开，新代码严格检查。
3. 持同一次独占维护锁执行备份和迁移。只有存量部署存在待执行迁移时备份；控制库逻辑转储、机构库备份及原件统一带清单和摘要，保留最近 3 份。
4. 持久升级状态补足进程文件锁的生命周期；失败后服务拒绝启动。恢复采用旧程序加升级前备份，不写反向迁移。
5. 服务启动只校验版本与升级状态；仅全新的空机构库可自动开通并执行全部机构迁移。
6. 完整恢复在破坏性操作前验证控制目录、精确派生库名、机构快照和原文包一一对应，拒绝符号链接；只执行随安装包发布的可信结构，备份自带SQL不执行。新增迁移结构必须补对应可信恢复版本，旧结构定义保留。
7. 业务备份按表分类；schema_migrations 不导出，demo_installations 导出并进入恢复白名单。保留追加式审计和全部历史数据。

## 影响

R1-2 已建立迁移、备份与失败恢复；R1-3 已完成后端装配；R1-5 实现外壳隔离。既有 entities 的 12 列与 relations 的 7 列不变。原接口、机构切换、下载的 workspace_id、窗口事件、请求代次和两个全局浮层继续兼容，只有通过逐项操作清单后才删除旧页面。

## R1-5 落地补充

新代码经@legacy声明别名读取宽松生成的旧类型；构建alias仍绑定原实现。类型负例防止strict被旧声明链关闭。旧门户采用display:contents避免整页空白高度。显式业务dirty与上传登记决定机构切换确认，不扫描DOM猜测编辑。新会话请求以独立AbortController隔离代次，权限键与旧布尔权限分别存放。懒加载保留旧视图期间，旧URL上下文不能覆盖最新浏览器地址；导航与图谱分别校验完整位置与固定挂载路由。
