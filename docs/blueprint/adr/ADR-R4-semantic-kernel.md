# ADR-R4 A：内核、发布检查与兼容验证

状态：已采纳　日期：2026-11-17　版本：1.3.0

1. 种类注册表统一维护 23 种既有与新增种类；新载荷使用严格模式，历史读兼容不回写。`entity_meta`、`job_schedule_state` 分别通过机构库 0004、控制库 0006 增加；可信恢复定义新增 v7，旧版精确定义保留。迁移只增加侧表，不改四张老表、编号及快照。调度器按北京时间生成每日回填任务，数据库租约避免多进程重复领取，任务使用限定机构的系统身份。
2. v1 与新能力共用要素内核，调用者保留旧角色、只读、机构与专业领域守卫。新建内容原子保存初始快照及 `_meta`；元数据和派生关系与正文一起提交。岗位、外部主体的 QG2/QG5 适用性与业务资产分类分开，不能通过直接写已发布状态绕过检查。旧已发布内容的读取不改变状态。
3. 派生关系只管理自身标记的边，技能与权责维护的关系仍由原领域管理。既有 45 种关系元组不改，`uses_method` 的既有含义保留，流程上下文增加步骤语义。通用对象接口的集团核心维护属后续范围，当前通用写入口拒绝伪造接口。业务卡确定性生成、缓存纯文本、授权后读取，不引入模型调用。
4. OXL 使用受限语法树与自定义求值器，禁止执行用户文本。属性必须在当前机构对应业务对象声明，不能凭测试输入推断。规则数值比较、日期计算及相关金额/期限语义纳入硬约束；普通指标算术本身不自动成为硬约束。规则“不符”保留人工核实声明，未知值不等同不符。
5. 五项检查由同一服务采集真实数据库事实，提交、审核、发布都检查。草稿预检只将即将原子保存的快照视为可满足，正式办理仍检查已保存快照。来源核对不可变锚点或真实台账表字段；未实现的陈述决定不伪装为有效依据。豁免限 QG1/QG3、独立审核人及非空理由，绑定内容指纹，编辑后失效；状态流转不误作内容编辑。出处豁免在折叠区外长期标注，硬约束另显示明确警示。
6. 配方 A 的制度原件归为 `regulation`，从明确原文补范围、条件、例外和生效日期；历史叙述日期不作为生效日期。默认提出本机构适用关系，原文点名的已有对象优先；采纳时人确认。非规则改为规则后先展示适用建议，再单独采纳。已采纳草稿的编辑用明确版本号；外部内容变更必须刷新查看并明确保存，只有审核流转造成的版本变化可照常重提。
7. 原 0.7.0 夹具只有 26 个要素（部门库 24 个）。AA2 按原始结构在迁移前扩充部门库到 200 个，176 个为明确标注的合成副本，其中 44 个带真实夹具锚点；全部原件及扩充后的四表逐行哈希分别校验。这不能表述成“200 个原始夹具记录”。浏览器逐个打开并检查实际卡片和出处高亮；修改哈希、删卡片文字、移除高亮的反例都必须失败。
8. 快速层每次推送无条件运行。R4 完整层以 `[R4-FULL]` 追加升级、全部旧浏览器与 R3+R4 动作、63 状态规范视觉矩阵和断网构建，不替换或缩小旧范围；最多两次。合成制度按 D2 补明确有效期与适用字段，旧状态、权限与下载断言保留。清理异常或未清理完不能出成功回执。
9. 本地使用可用的 Chromium 156；锁定 Playwright Chromium 1255 的下载在当前环境受限，规范矩阵以 CI 固定浏览器为准。改动页面按 1366×768 与基准页 03/04/05 审阅，无像素门。真实模型只用隔离合成材料，经浏览器与 SDK，密钥仅在子进程环境；失败保留，最终三连无重试、每次新库，记录模型、地址、耗时、数字拦截、修订和门禁枚举。
10. 真实提炼可能把规范条款误分为技能或漏提数据单位；主线核对人依据原文在既有编辑入口纠正分类、单位和粒度，不删除候选、不补造技能执行证明、不绕过门禁。演练的这类人工处理须检查实际保存、版本变化与重新计算的门禁。报告提示词明确保留有依据的数量及单位，同时不把条款序号、清单计数或表格行数改写为无依据的业务数量；数字核验器不放宽。模型提炼回退为本地条款保留时，验收仍记失败，不能算作真实模型成功。
11. 提炼提示词显式声明发布字段的文字类型，短字段引用须包含足够的连续原文上下文，保留标点和空白；严格类型、逐字引文与覆盖校验保持不变。服务日志仅记录固定允许列表内的失败码，不记录异常原文、来源正文、候选、标识或密钥。离线扫描仅在七个固定 Schema 文件中识别合法 JSON 的首个根 `$schema` 静态标识；不豁免远程引用或任何运行时请求，测试反例证明同一地址用于请求仍失败。

12. 完整层旧页面操作必须等响应式导航和真实标题就绪，再测原完整链接与结构，不以加载壳通过验收；实际关闭菜单和缺标题的反例仍失败。离线演练显式开通一次性机构，并逐库检查迁移版本与新侧表，控制库单独启动成功不能代表机构迁移已验证；运行期网络隔离与全部安装/构建/HTTP 断言保持。

R4-B 的机构发布版本、全文检索、权限可见范围及完整新种类编辑器保持原计划；本段不提前开放。Windows 原生验收继续由原流程负责，Linux 的既有跳过不算原生通过。

## R4-A.1 门禁办理、事实来源与旧入口

2026-11-19 按 D11–D15 实施。原子检查分别判定出处、口径、条件、关系和版本。提交阶段允许建设人员对出处、条件的具体缺口逐项申请。审核人员对同一版本、同一内容逐项作出决定，发布时重新检查全部五项。在本次修订内累计内容编辑人，独立性校验覆盖旧页、能力接口和专用工作台。升级前已待审核且没有新修订记录的条目沿用原规则。

制度文件的施行日期来自针对本文件的句子，或由核对人填写一次。保存文件日期和默认适用范围的依据；业务条款的条件和例外只接受本条引用、明确手填或人工批量确认。模型输出的引文须逐字定位，混合批次只剔除不合格候选，无有效结果时限一次重试。方案逐条决定送审资格。已采纳的未提交草稿支持放弃和重新分类，相关版本及人员操作可追溯。

旧页面经同一草稿进入补齐或申请。授权规则通过原审批规则校验保存，技能通过其专用测试与依赖校验提交。审核与发布界面只展示当前机构有权核对的事实和来源。历史未知类型继续通过原有接口使用，回填跳过该行；异常旧判定式可读，保存新内容时严格检查形状。内核固定北京时间偏移，脱离系统时区数据库仍可运算。 [裁决及动作清单](../rounds/R4-PLAN.md)
