# ADR-R3 界面基础、兼容边界与验证方式

状态：已采纳　日期：2026-11-17　相关轮次：R3 / 1.2.0

## 决定与理由

1. 页面布局只有 `PageLayout` 定义；新页面不得自建页边距或最大宽度。分栏按真实视口收起导航，窄屏出处进入抽屉；专业视图只增加结构化内容。默认简洁不覆盖已保存偏好。依据 R3 D1–D5、D9–D11，无新增权限语义。
2. 旧页面保留业务 DOM、路由、请求和职责分离，仅在 `legacy-root` 内作用域化样式。原来路/业务归属与可见范围控件使用稳定 portal host 移入标题区域，移动不卸载控件，避免丢失未保存选择；直接访问详情时补返回入口。旧 AI 按钮改中性底和深色文字，原 primary 保留品牌红，覆盖旧专属选择器，避免去渐变后白底白字。
3. 读契约兼容已存在的正文/条件 JSON、历史来源与空进度；新写请求仍严格校验。代理报告组件类型合并入生成组件库，REST v2 OpenAPI 仍只导出 `/api/v2/` 路径；同名模型冲突立即失败。GET run 使用 `response_model_exclude_unset` 保留缩小范围/撤权后删除回答字段的原语义，显式空值仍保留，不能由类型默认值补回。目录来源标题只读当前机构已授权原材料，联邦条目只返回授权机构来源，不跨库补标题。
4. 报告首次数字/引用核验失败后自动修订一次，再走原严格核验；失败、离页、机构切换与重复点击有独立保护。真实演练发现开场白与总结漏引用、条款序号被误算成条目数，故系统和修订提示明确事实段/表格每行自带真实来源链接，不输出无依据数量；后端核验规则不变。报告摘要选择有实际引用的段落，上标与该段引用一致；修订前后默认折叠且保留完整内容。应用回答的已知引用编号按对应run及当前授权资料映射业务名称，只改可见正文和链接标签，不改链接地址、原答或原文；跨机构同编号或名称冲突不强行映射。禁止自动循环或把本地/模拟输出标成真实模型。
5. Linux tmpfs 判断用已打开目录的 `/proc/self/fdinfo` mount id 对照 mountinfo，解决挂载覆盖时错误选到隐藏只读挂载；仍拒绝磁盘、只读、符号链接、缺失/重复/非法挂载信息。没有磁盘回退。
6. 按 R3 D8/D9，像素差只作诊断；63 张规范图在固定 GitHub Actions 浏览器生成，经不超过12格拼图逐图审阅，基线与 compare 同提交。第一次完整层在旧权限回归中提前失败、未执行截图，故以 `[R3-VISUAL]` 定向运行矩阵；首次只生成33图且有axe失败，全部拒绝入库，修复按钮名称、旧材料链接区分与审计历史动作筛选后再生成完整矩阵，仍最多两次完整层。原生125%缩放、PNG物理尺寸、axe严重问题、结构和动作结果继续阻断。每次 CI 只保留一个汇总构件，排除重复HTML和失败trace目录，不删原始指标或结果摘要；本地演练回执与CI摘要仅留work，结论写入报告，不另提交证据类文件。泄漏扫描按可见块拼接行内文字，避免强调/代码节点拆词造成漏报或误报；原模式、闭合折叠、隐藏节点及专业技术区边界保留。
7. 真实模型验证只使用演练合成制度与隔离夹具，经真实浏览器操作；密钥只从进程环境读取。live 输出不保存回答正文、页面全文或原始浏览器错误，仅记录步骤、时间、核验代码、安全文件行列和枚举异常类别计数；失败如实计入，收尾连续三次从独立新夹具开始。
8. 第二次完整层的SDK界面回归发现后台任务深链未展开助手，修复后原单例又发现停止按钮超出视口。保留原断言，补Esc后同URL重开、刷新深链与持续运行检查；助手任务区域有界滚动，停止操作保持可见。两次完整层额度已用完，按D1只复验失败项及此前未执行的验收；每项记录实际SHA，明确没有单次全绿的最终完整CI，不通过重跑全量或弱化断言掩盖失败。

9. 交接复核发现U6集成应用曾误按旧页部分结构门处理，交付前补齐共享骨架和简洁/专业技术内容分层。采用展示插槽复用原业务体，原读写接口、manage_users/readonly、版本字段、一次性令牌清理及机构切换守卫继续由原实现承担；没有新增请求或后端契约。旧路由与文件保留，并将该路由提升为新页完整结构/泄漏检查。`[R3-INTEGRATION]`只执行新增6个组件用例及该页真实操作，不重复已完成范围。原词条值逐项不变，仅新增28个集成页词条。

不建议另改蓝图：以上均落实本轮已批准裁决或维持既有兼容/安全契约。无新增表、迁移、能力编号或依赖；Node22、Python3.12、MySQL8.4及受保护流水线不变。
